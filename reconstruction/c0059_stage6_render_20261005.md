# Candidate0059 Stage6 pointer-backed render tracking

Stage6 restores the render queue/dequeue state that the legacy Xiaomi MIGT
device contract depends on.

The implementation is semantic rather than a raw donor copy: render flags live
in the KABI-safe `pkg_task_state()` backing store, while the two stock render
identities remain `RENDER_QUEUE_THREAD` and `RENDER_DEQUEUE_THREAD`.

Restored source/API:
- `migt_render_state_init()`
- `update_render_info()`
- `reset_render_info()`
- `is_render_thread()`
- stock render task bit masks

Initialization is called from the already-restored `migt_sched_init()`.

This stage intentionally does not register `/dev/migt`, process ioctls, alter
cpufreq/core_ctl/thermal policy, expose Metis, or implement iorap.

After a compile PASS, the legacy MIGT ioctl shell can be added without lying
about QUEUE/DEQUEUE behavior because the render state it controls will actually
exist. SET_CEILING must remain unsupported until the corresponding frequency
ceiling semantics are ported.
